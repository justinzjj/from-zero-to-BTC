基础知识 / 04

有限域与扩展欧几里得算法

模运算里的除法如何定义？

a · a⁻¹ ≡ 1 (mod p)
ax + py = gcd(a,p) = 1
  • 加、减、乘都取模；除以a改为乘a的逆元。
  • 辗转相除递推余数，同时递推系数；gcd不变，线性组合关系不变。
  • 只有 gcd(a,p)=1 才有逆元；不能求0的逆。
例：3 × 13 = 39 ≡ 1 (mod 19)
因此 3⁻¹ mod 19 = 13

欧几里得除法步数 O(log p)；大整数除法本身也有成本。曲线坐标模p，签名标量模n。

基础知识 / 05

椭圆曲线点群与 Point 结构

点加法为什么不是坐标分别相加？

y² ≡ x³ + ax + b (mod p)
struct Point {
    int x = 0, y = 0;
    bool infinity = true;
};
  • 加入无穷远点 O，作为加法单位元。
  • P+O=P；P+(−P)=O。
  • 负点为 (x,−y mod p)；输入必须在曲线上。

Point 是小参数教学结构；真实曲线坐标是256位，库对象还可能含投影坐标及内部状态。

基础知识 / 06

椭圆曲线点加与倍点

怎样从两个曲线点计算另一个曲线点？

P ≠ Q：λ = (yQ−yP)(xQ−xP)⁻¹ mod p
P = Q：λ = (3xP²+a)(2yP)⁻¹ mod p
xR = λ²−xP−xQ
yR = λ(xP−xR)−yP　(mod p)

先处理 O、互为负点与 y=0 的倍点；这些分支结果可能为 O，不能先尝试求逆。

基础知识 / 07

二进制倍加与公钥生成

如何用 O(log d) 次点运算计算 Q=dG？

R = O, P = G
while k > 0:
    if k & 1: R = R + P
    P = P + P
    k >>= 1
return R
  • d 在 [1,n−1]，G 是基点，n 是G的阶。
  • 每轮处理一位；已累积部分与剩余倍点部分仍对应原来的 dG。
  • b位标量最多b次倍点、b次条件加法。
  • 从Q反推d依赖椭圆曲线离散对数难题。

教学循环带秘密相关分支，不用于生产。Core 的窗口、预计算、坐标优化属于实现选择，不是共识指定的循环。

基础知识 / 09

ECDSA 签名算法

私钥如何把消息摘要变成 (r,s)？

消息m摘要整数znonce kR=kG输出(r,s)
r = xR mod n
s = k⁻¹(z + rd) mod n
  • 私钥d和nonce k满足 1≤d,k
  • r或s为0时重新生成nonce。
  • 输出签名，不输出d或k；nonce由成熟库安全管理。

本课 sign_message 内部做一次 SHA-256；Bitcoin P2WPKH 使用 BIP143 预映像的双SHA-256。

基础知识 / 10

ECDSA 验签与正确性

只有公钥 Q，为什么也能验证？

w=s⁻¹ mod n，u₁=zw mod n，u₂=rw mod n
X=u₁G+u₂Q
  • 先检查 r,s 范围，公钥编码与曲线有效性。
  • 若 X=O 拒绝；否则检查 xX mod n = r。
Q=dG ⇒ X=(z+rd)s⁻¹G=kG=R

等式证明正确签名的一致性，不单独证明不可伪造；安全还依赖参数、随机数、公钥绑定和实现。

BIP143：Bitcoin P2WPKH 签名路径

输入 / 旧币金额 / scriptCode / 输出 / 模式BIP143预映像双SHA-256ECDSADER + 模式字节

BIP340 Schnorr：Taproot 的签名算法

同一条曲线，为什么不是同一种签名？

s = k + ed mod n　　R = sG − eP
  • 挑战 e 用规定的带标签哈希绑定R、公钥P和消息。
  • 还必须遵循偶y规范化、nonce生成、范围检查，不能只实现核心等式。
  • x-only公钥32字节，签名本体64字节；显式非默认签名模式可再加1字节。
  • Taproot 输出公钥还涉及 BIP341 tweak。

本讲完整推导ECDSA，Schnorr完整算法放E2。不能把“Bitcoin使用ECDSA”扩大成所有输出类型都只用ECDSA。

ECDSA 的运算与存储开销

成本来自消息长度，还是曲线计算？

操作主要工作
密钥生成安全随机标量 + dG
签名O(m)消息哈希 + kG + 标量模逆/乘法
验签O(m)消息哈希 + u₁G + u₂Q + 点加
朴素倍加O(b)点运算；每次含模乘与模逆
优化方向投影坐标减少模逆；窗口/预计算；常数时间实现

固定256位曲线不等于没有成本。实际联合乘法和上下文管理使签名/验签耗时不能按点乘次数简单推算。

代码：模逆与二进制倍加

保持什么不变量，才能得到正确点乘结果？

int inverse(int x, int m) {
    int r = m, next_r = mod(x, m), t = 0, next_t = 1;
    while (next_r) {
        int q = r / next_r;
        int tmp = r - q * next_r;
        r = next_r; next_r = tmp;
        tmp = t - q * next_t;
        t = next_t; next_t = tmp;
    }
    if (r != 1) throw std::invalid_argument("inverse does not exist");
    return mod(t, m);
}
Point multiply(int k, Point q) {
    if (k < 0) throw std::invalid_argument("negative scalar");
    Point result;
    while (k) {
        if (k & 1) result = add(result, q);
        q = add(q, q);
        k >>= 1;
    }
    return result;
}

inverse 同时递推余数与系数；multiply 每轮取最低位、倍点、右移。先检查合法输入，再做群运算。

代码：小曲线 ECDSA 签名

nonce与签名范围在哪里约束？

std::optional<Signature> sign_digest(int z, int d, int k) {
    if (d < 1 || d >= n || k < 1 || k >= n)
        throw std::invalid_argument("d and k must be in [1,n-1]");
    int r = multiply(k, G).x % n;
    if (r == 0) return std::nullopt;
    int s = mod(inverse(k, n) * (mod(z, n) + r*d), n);
    if (s == 0) return std::nullopt;
    return Signature{r, s};
}

r或s为0返回空值，调用者重新选择nonce。这里z已是摘要整数，不再哈希。

代码：小曲线 ECDSA 验签

哪些边界必须在接受签名前检查？

bool verify_digest(int z, Signature sig, Point public_key) {
    if (sig.r < 1 || sig.r >= n || sig.s < 1 || sig.s >= n) return false;
    if (!on_curve(public_key) || !multiply(n, public_key).infinity) return false;
    int w = inverse(sig.s, n);
    int u1 = mod(mod(z, n)*w, n), u2 = mod(sig.r*w, n);
    Point x = add(multiply(u1, G), multiply(u2, public_key));
    return !x.infinity && x.x % n == sig.r;
}

检查r/s范围、公钥在曲线上且nQ=O、计算结果不是O，最后比较x坐标模n。生产授权使用成熟密码学库。

什么结果才能判定签名被接受？

inline bool verify_message(EVP_PKEY* pub,const Bytes& message,const Bytes& signature) {
    Context ctx(EVP_MD_CTX_new(),EVP_MD_CTX_free);require(bool(ctx),"verify context");
    require(EVP_DigestVerifyInit(ctx.get(),nullptr,EVP_sha256(),nullptr,pub)==1,"verify init");

    return EVP_DigestVerify(ctx.get(),signature.data(),signature.size(),message.data(),message.size())==1;
}
