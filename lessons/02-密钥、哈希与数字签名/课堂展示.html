secp256k1、ECDSA 与 Schnorr

分别是什么？在签名和验签中负责什么？

名称是什么作用与Bitcoin用途
secp256k1一套标准椭圆曲线参数提供密钥和签名运算的底层基础；ECDSA和BIP340 Schnorr都使用它。
ECDSA椭圆曲线数字签名算法用私钥产生签名，用公钥验证；Bitcoin传统与SegWit v0使用，本课实际操作它。
Schnorr（BIP340）另一种数字签名算法的Bitcoin规范同样负责签名与验签；用于Taproot，本课只认识用途。
选择secp256k1生成密钥用ECDSA签名 / 验签

secp256k1不是签名算法；ECDSA和Schnorr是两种签名方案。libsecp256k1是实现库的名字；本课通过OpenSSL EVP调用secp256k1上的ECDSA。

私钥留在钱包，验证端究竟拿到什么？

签名端

私钥 + 消息字节ECDSA签名接口签名字节

  • 私钥只用于生成签名，不发送给验证端。
  • 验证端使用预期授权者的公钥，不能接受任意替换的公钥。
  • 编码或哈希约定必须一致；任何一项输入不对应，都不能当作有效授权。

签名与验签：步骤伪代码

输入、算法调用、错误分支与返回值

签名

FUNCTION SignPayment(sk, draft) → Bytes
    REQUIRE IsValidSecretKey(sk, secp256k1)

    message ← Encode(draft)
    digest  ← SHA256(message)
    signature ← ECDSA.SignDigest(sk, digest)

    IF signature = ERROR THEN
        RAISE SigningError
    END IF

    RETURN DER.Encode(signature)
END FUNCTION

验签

FUNCTION VerifyPayment(pk, draft, encodedSig) → Boolean
    IF NOT IsValidPublicKey(pk, secp256k1) THEN
        RETURN FALSE
    END IF
    signature ← DER.Decode(encodedSig)
    IF signature = ERROR THEN
        RETURN FALSE
    END IF
    message ← Encode(draft)
    digest  ← SHA256(message)
    RETURN ECDSA.VerifyDigest(pk, digest, signature)
END FUNCTION

ECDSA使用secp256k1；pk是预期授权者的公钥。SignDigest / VerifyDigest的内部步骤见下两页；实际EVP消息接口将SHA-256与ECDSA合并执行，调用者只传原文。

实验尝试 / 10

ECDSA.SignDigest：签名内部步骤

输入私钥与32字节摘要，输出签名数对。

FUNCTION ECDSA.SignDigest(d, digest) → (r, s)
    REQUIRE 1 ≤ d < n AND Length(digest) = 32
    z ← BytesToIntegerBE(digest)
    LOOP
        k ← SecureRandomInteger(1, n − 1)
        R ← ScalarMultiply(k, G)
        r ← XCoordinate(R) MOD n
        IF r = 0 THEN
            CONTINUE
        END IF
        s ← (ModInverse(k, n) × (z + r × d)) MOD n
        IF s ≠ 0 THEN
            RETURN (r, s)
        END IF
    END LOOP
END FUNCTION

d：私钥；G：标准基点；n：G的阶；k：内部nonce。点运算在secp256k1上执行；标量计算取模n。r或s为0时重新生成k。

SEC 1 v2.0 §4.1.3

ECDSA.VerifyDigest：验签内部步骤

只使用预期公钥、同一摘要和签名，不需要私钥。

FUNCTION ECDSA.VerifyDigest(Q, digest, (r, s)) → Boolean
    IF Length(digest) ≠ 32 THEN RETURN FALSE END IF
    IF Q = O THEN RETURN FALSE END IF
    IF NOT IsOnSecp256k1(Q) THEN RETURN FALSE END IF
    IF ScalarMultiply(n, Q) ≠ O THEN RETURN FALSE END IF
    IF NOT (1 ≤ r < n AND 1 ≤ s < n) THEN
        RETURN FALSE
    END IF
    z  ← BytesToIntegerBE(digest)
    w  ← ModInverse(s, n)
    u1 ← (z × w) MOD n
    u2 ← (r × w) MOD n
    X  ← PointAdd(ScalarMultiply(u1, G),
                  ScalarMultiply(u2, Q))
    IF X = O THEN RETURN FALSE END IF
    RETURN (XCoordinate(X) MOD n) = r
END FUNCTION

O：无穷远点；IsOnSecp256k1检查坐标范围与曲线关系。摘要按大端转整数；此处限定SHA-256与secp256k1，DER解析由外层完成。

摘要、缓冲区与错误处理如何衔接？

inline Bytes sign_message(EVP_PKEY* key,const Bytes& message) {
    Context ctx(EVP_MD_CTX_new(),EVP_MD_CTX_free);require(bool(ctx),"sign context");
    require(EVP_DigestSignInit(ctx.get(),nullptr,EVP_sha256(),nullptr,key)==1,"sign init");
    std::size_t size=0;require(EVP_DigestSign(ctx.get(),nullptr,&size,message.data(),message.size())==1,"signature size");

实验尝试 / 16

代码：ECDSA 公开验签

什么结果才能判定签名被接受？

inline bool verify_message(EVP_PKEY* pub,const Bytes& message,const Bytes& signature) {
    Context ctx(EVP_MD_CTX_new(),EVP_MD_CTX_free);require(bool(ctx),"verify context");
    require(EVP_DigestVerifyInit(ctx.get(),nullptr,EVP_sha256(),nullptr,pub)==1,"verify init");
    // Return 0 or a malformed-signature error as verification failure; init errors throw.
    return EVP_DigestVerify(ctx.get(),signature.data(),signature.size(),message.data(),message.size())==1;
}

只有返回1才接受；0或畸形签名错误都不是成功。Core 对应 CPubKey::Verify → secp256k1_ecdsa_verify。

BIP143：Bitcoin P2WPKH 签名路径

真实交易签名覆盖的是什么？

输入 / 旧币金额 / scriptCode / 输出 / 模式BIP143预映像双SHA-256ECDSADER + 模式字节
  • 签名与压缩公钥一起进入对应输入的见证。
  • 验证者重建同一摘要，并核对公钥与旧输出条件。
