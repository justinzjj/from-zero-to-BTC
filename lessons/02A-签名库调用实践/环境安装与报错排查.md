# 02A 实践：环境安装与报错排查

适用代码：`code/lesson-02-practice/` 中的 5 个独立 C++ demo。

目标：安装编译器和 OpenSSL 开发库，运行 demo；遇到错误时，能够判断应该修改环境、编译命令，还是代码。

## 1. 先分清楚：到底哪里报错

**先在终端运行 `run.sh`，以实际编译结果判断程序是否能运行。** 编辑器中的红色波浪线与编译结果可能不同。

| 现象 | 所处阶段 | 优先检查 |
|---|---|---|
| VS Code 标红 `openssl/evp.h`，但终端运行成功 | 编辑器分析 | C/C++ 扩展的编译器和头文件路径 |
| `c++: command not found` | 编译器启动前 | 编译器是否安装、终端是否正确 |
| `openssl/evp.h: No such file or directory` | 编译 | 开发头文件是否安装、`-I` 参数 |
| `undefined reference to EVP_...` 或 `Undefined symbols` | 链接 | 是否链接 OpenSSL、库版本与架构是否一致 |
| 找不到 DLL、`Library not loaded` | 启动程序 | 动态库是否存在、运行环境是否正确 |
| 程序输出签名失败、验签失败 | 程序运行 | 返回值、消息、公钥、签名是否匹配 |

## 2. 需要安装什么

| 工具 | 作用 |
|---|---|
| VS Code + Microsoft 的 C/C++ 扩展 | 编写代码、语法提示、查看错误 |
| C++ 编译器 | 把 `.cpp` 编译成可执行程序；使用 Clang 或 GCC |
| OpenSSL 开发文件 | 头文件提供函数声明，库文件提供函数实现 |
| `pkg-config` | 告诉编译器 OpenSSL 的头文件和库在哪里 |
| Bash | 执行课程提供的 `run.sh` |

仅安装 VS Code 或 C/C++ 扩展，不会自动安装上述完整环境。能运行 `openssl version`，也不代表已经有开发头文件和链接库。

课程代码使用 OpenSSL 3 引入的接口，已验证版本为 OpenSSL 3.6.4。建议课堂统一使用 OpenSSL 3.x；脚本只检查版本至少为 3.0，并不保证所有更新主版本已经验证。

## 3. 按操作系统安装

只执行自己系统对应的一组。安装完成后，再进入第 4 节。

### 3.1 macOS：Apple Silicon 和 Intel

在“终端”执行：

```bash
xcode-select --install
```

按弹窗安装命令行开发工具；如果提示已经安装，可以继续。

如果 `brew --version` 提示找不到命令，先按 [Homebrew 官网](https://brew.sh/) 的步骤安装，并完成安装结束时提示的 shell 环境设置。

```bash
brew install openssl@3 pkgconf
export PKG_CONFIG_PATH="$(brew --prefix openssl@3)/lib/pkgconfig:${PKG_CONFIG_PATH:-}"
c++ --version
pkg-config --modversion openssl
pkg-config --cflags --libs openssl
```

`export` 命令对当前终端生效，新终端中可以重新执行。它使用实际安装位置，兼容 Apple Silicon 常见的 `/opt/homebrew` 与 Intel 常见的 `/usr/local`。

现有 `run.sh` 会自动识别 `/opt/homebrew/opt/openssl@3`；Intel Mac 或非默认安装位置需要先执行上面的 `export`。

安装与路径配置依据：[OpenSSL 3 Homebrew 包](https://formulae.brew.sh/formula/openssl%403)、[Homebrew 外部编译依赖配置](https://docs.brew.sh/How-to-Build-Software-Outside-Homebrew-with-Homebrew-keg-only-Dependencies)。

### 3.2 Windows：MSYS2 UCRT64（x64）

此方案使用同一套 GCC、OpenSSL 和终端，适用于常见 Intel/AMD 64 位 Windows。

1. 从 [MSYS2 官网](https://www.msys2.org/) 安装 MSYS2，例如安装到 `C:\msys64`。
2. 从开始菜单打开 **MSYS2 UCRT64**。
3. 在这个窗口更新软件包：

```bash
pacman -Syu
```

如果更新要求关闭终端，按提示关闭，重新打开 **MSYS2 UCRT64**，再执行一次 `pacman -Syu` 完成更新。

然后安装：

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-openssl mingw-w64-ucrt-x86_64-pkgconf
```

检查：

```bash
echo "$MSYSTEM"
command -v c++
command -v pkg-config
pkg-config --modversion openssl
```

第一项应为 `UCRT64`；编译器和 `pkg-config` 应来自 `/ucrt64/bin`。

本指南的 Bash 命令在 **UCRT64 窗口**执行。PowerShell、CMD、Git Bash 和 MSYS2 的不同环境不能直接混用。可以先用 VS Code 编辑、UCRT64 窗口编译，不必一开始配置运行按钮。

MSYS2 是滚动更新的软件仓库，安装命令不锁定 OpenSSL 主版本。如果版本输出已经不是 3.x，需要记录版本并重新验证全部 demo；本课程现有验证记录不能代替该版本的验证。希望严格统一到 OpenSSL 3.x 的 Windows 课堂也可使用 WSL 中的 Ubuntu 24.04，按下一节安装，并通过 VS Code 的 WSL 扩展在 Linux 环境中打开项目。

依据：[MSYS2 环境说明](https://www.msys2.org/docs/environments/)、[OpenSSL 软件包](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-openssl)、[pkgconf 软件包](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-pkgconf)。

### 3.3 Ubuntu / Debian 系列 Linux

以 Ubuntu 24.04 为例：

```bash
sudo apt update
sudo apt install build-essential pkg-config libssl-dev
c++ --version
pkg-config --modversion openssl
```

确认 OpenSSL 为 3.x。旧发行版如果只提供 1.1.1，建议使用较新的教学环境；本课程使用的 `EVP_PKEY_Q_keygen` 不能直接在 1.1.1 上编译。

`libssl-dev` 是开发包，包含课程需要的 OpenSSL 头文件和链接文件。WSL 中安装的 Linux 库要与 Linux 编译器一起使用，不能搭配 Windows 的 `g++.exe`。

## 4. 第一次运行：从最小 demo 开始

先在终端进入自己的 `from-zero-to-BTC` 文件夹。下方路径只是示例，请替换成实际路径；有空格或中文时保留引号。

macOS / Linux 示例：

```bash
cd "/你的项目位置/from-zero-to-BTC"
```

Windows UCRT64 示例：如果项目位于 `C:\Users\student\Desktop\from-zero-to-BTC`：

```bash
cd "/c/Users/student/Desktop/from-zero-to-BTC"
```

确认位置并运行：

```bash
pwd
ls code/lesson-02-practice
bash code/lesson-02-practice/run.sh 01
```

第一个 demo 应输出 SHA-256 摘要和 `PASS`。成功后运行全部：

```bash
bash code/lesson-02-practice/run.sh
```

单独运行第 4 个：

```bash
bash code/lesson-02-practice/run.sh 04
```

每个 `.cpp` 都有自己的 `main`，必须独立编译。不要将 5 个文件一起编译成一个程序，否则会出现 `multiple definition of main` / `duplicate symbol _main`。

生成的程序放在 `code/build/lesson-02-practice/`。每次执行脚本都会重新编译选中的 demo，避免运行旧文件。

### 4.1 怎样判断成功

| Demo | 预期结果 |
|---|---|
| 01 | `abc` 的摘要为 `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`；修改消息后不同 |
| 02 | 公钥导出、导入、再次导出成功，数据一致 |
| 03 | 成功生成非空签名；签名内容和长度允许变化 |
| 04 | `original=1`、`changed_message=0`、`changed_signature_rejected=1`、`wrong_key=0` |
| 05 | `original=1`、`changed_amount=0`、`changed_receiver=0` |

`changed_signature_rejected=1` 表示“成功拒绝了修改后的签名”，不是说修改后的签名通过验签。验签函数本身返回 `1` 才表示签名有效。

## 5. VS Code 有红线，但程序可以运行

### 5.1 先打开整个文件夹

使用“文件 → 打开文件夹”打开 `from-zero-to-BTC`，安装 Microsoft 的 **C/C++** 扩展。

配置文件属于当前打开的工作区：如果打开的是上一级“家教”文件夹，配置应在“家教/.vscode”；如果打开的是 `from-zero-to-BTC`，配置应在其 `.vscode` 下。不要把配置放到另一个未打开的文件夹后期待自动生效。

### 5.2 设置 IntelliSense

打开命令面板：Windows/Linux 用 `Ctrl+Shift+P`，macOS 用 `Cmd+Shift+P`。选择：

```text
C/C++: Edit Configurations (UI)
```

填写下面的对应项。路径按自己的安装位置调整：

| 环境 | Compiler path | Include path 增加项 | IntelliSense mode |
|---|---|---|---|
| Apple Silicon Mac | `/usr/bin/clang++` | `/opt/homebrew/opt/openssl@3/include` | `macos-clang-arm64` |
| Intel Mac | `/usr/bin/clang++` | `/usr/local/opt/openssl@3/include` | `macos-clang-x64` |
| Windows UCRT64 | `C:/msys64/ucrt64/bin/g++.exe` | `C:/msys64/ucrt64/include` | `windows-gcc-x64` |
| Ubuntu x64 / WSL Ubuntu x64 | `/usr/bin/g++` | 通常由编译器自动发现 | `linux-gcc-x64` |

C++ standard 选 `c++17`。ARM Linux 使用匹配的 `linux-gcc-arm64` 模式。

Mac 可以运行 `brew --prefix openssl@3` 获取路径，再在后面加 `/include`。头文件路径应指向包含 `openssl` 文件夹的 **include 目录**，不要填到 `include/openssl`。

也可以通过 `C/C++: Edit Configurations (JSON)` 修改 `c_cpp_properties.json`。例如 Windows UCRT64：

```json
{
  "configurations": [
    {
      "name": "UCRT64",
      "compilerPath": "C:/msys64/ucrt64/bin/g++.exe",
      "intelliSenseMode": "windows-gcc-x64",
      "cppStandard": "c++17",
      "includePath": [
        "${workspaceFolder}/**",
        "C:/msys64/ucrt64/include"
      ]
    }
  ],
  "version": 4
}
```

已有配置时修改对应项，保留其他项目需要的配置。保存后如仍标红，可以执行 `C/C++: Reset IntelliSense Database`，然后 `Developer: Reload Window`。

如果项目设置了 `configurationProvider` 或 `compile_commands.json`，它们可能优先提供配置。用 `C/C++: Log Diagnostics` 查看当前文件实际使用的编译器和 include 路径，再修改生效的配置来源。

**`c_cpp_properties.json` 配置的是编辑器分析。实际编译的参数来自 `run.sh` 或构建任务。** 修改 includePath 不会自动给编译命令增加链接库。

依据：[VS Code IntelliSense 配置](https://code.visualstudio.com/docs/cpp/configure-intellisense)、[C/C++ 配置字段说明](https://code.visualstudio.com/docs/cpp/customize-cpp-settings/)。

## 6. 编译和运行报错对照表

优先看输出中的**第一条错误**。后面的很多错误可能只是由第一条引起。

| 错误或现象 | 常见原因 | 处理方法 |
|---|---|---|
| `bash: command not found` / PowerShell 找不到 bash | 终端环境不对 | Windows 打开 MSYS2 UCRT64；本指南不在 PowerShell 执行脚本 |
| `c++: command not found` | 未装编译器或 PATH 不对 | 按第 3 节安装；Windows 确认 UCRT64 |
| 找不到 `pkg-config` | 缺少参数查询工具 | Mac 安装 `pkgconf`；Windows 安装 UCRT64 pkgconf；Ubuntu 安装 `pkg-config` |
| `Package openssl was not found` | 未安装开发包，或找不到 `.pc` 文件 | 安装对应开发包；Mac 重新执行第 3.1 节的 `export` |
| 脚本直接退出，没有开始编译 | OpenSSL 版本检查失败等 | 执行下方版本检查；必要时用 `bash -x` 查看停在哪条命令 |
| `openssl/evp.h` 或 `openssl/x509.h` 找不到 | 头文件缺失或缺少 `-I` | 用课程脚本编译；检查 `pkg-config --cflags openssl` |
| `iostream` 找不到 | C++ 编译环境有问题 | 检查 `c++ --version`；补齐编译工具，避免误用纯 C 编译配置 |
| `EVP_PKEY_Q_keygen` 未声明 | 使用旧头文件 | 检查 OpenSSL 版本与 `pkg-config --cflags openssl`；统一到 OpenSSL 3 |
| `undefined reference` / `Undefined symbols` 指向 `EVP_...` | 没有链接库或链接了不匹配的库 | 使用脚本；检查 `pkg-config --libs openssl`，库参数放在源文件或目标文件后面 |
| `library not found for -lcrypto` / `cannot find -lcrypto` | 链接库缺失或 `-L` 路径不对 | 安装开发包，核对库路径，不要只复制 `.h` 文件 |
| `multiple definition of main` | 多个 demo 一起编译 | 一次只编译一个 `.cpp`，或使用脚本逐个编译 |
| `incompatible architecture` / `file format not recognized` | ARM/x64 或编译工具链混用 | 编译器和库统一架构；Windows 不混用 UCRT64、MINGW64、MSVC 的库 |
| 缺少 `libcrypto-*.dll` | 没有在正确运行环境启动 | 在 UCRT64 终端运行；检查 `C:/msys64/ucrt64/bin` 是否存在对应 DLL，必要时重装该环境的 OpenSSL 包 |
| Mac `Library not loaded` | 依赖库移动或升级后旧程序失效 | 确认 Homebrew OpenSSL 存在，用课程脚本重新编译 |
| `Permission denied` 执行 run.sh | 脚本没有可执行权限 | 使用 `bash code/lesson-02-practice/run.sh`，无需依赖执行权限 |
| `No such file or directory` 指向源码或脚本 | 当前目录不正确 | 用 `pwd` 和 `ls` 确认位于项目根目录 |
| `\r` / `bad interpreter` 等错误 | 脚本被保存为 Windows CRLF 换行 | 在 VS Code 右下角将 run.sh 的 CRLF 改为 LF，保存再运行 |
| `unused variable` 被当作 error | 脚本启用了 `-Werror` | 使用或删除未使用变量，修复具体警告 |
| 点击右上角运行失败，终端脚本却成功 | 运行按钮没有带 OpenSSL 参数 | 先用终端脚本；不要使用默认 `g++ 文件.cpp` 代替课程编译命令 |

版本检查：

```bash
pkg-config --modversion openssl
pkg-config --atleast-version=3.0 openssl
echo $?
```

最后输出 `0` 表示版本条件满足；非 `0` 表示不满足或查询失败。`echo $?` 必须紧跟被检查的命令。

查看脚本执行过程：

```bash
bash -x code/lesson-02-practice/run.sh 01
```

## 7. 编译命令到底做了什么

下面在项目根目录执行，仅用于理解或排查；正常上课可以直接用 `run.sh`。适用 macOS/Linux/UCRT64 的 Bash 类终端：

```bash
mkdir -p code/build/lesson-02-practice
c++ -std=c++17 -Wall -Wextra -Werror -O2 \
  $(pkg-config --cflags openssl) \
  code/lesson-02-practice/01_hash.cpp \
  -o code/build/lesson-02-practice/01_hash \
  $(pkg-config --libs openssl)
```

编译成功后运行：

```bash
./code/build/lesson-02-practice/01_hash
```

| 参数 | 含义 |
|---|---|
| `c++` | 调用 C++ 编译器 |
| `-std=c++17` | 使用 C++17 语言标准 |
| `-Wall -Wextra` | 开启常用警告 |
| `-Werror` | 将警告作为错误处理 |
| `-O2` | 开启优化 |
| `pkg-config --cflags openssl` | 生成头文件搜索参数，常见为 `-I...` |
| `-o 路径` | 指定输出程序的位置 |
| `pkg-config --libs openssl` | 生成库路径和链接参数，常见为 `-L... -lssl -lcrypto` |

`$(...)` 表示先运行括号内的命令，将其输出作为编译参数。`-I` 解决“找函数声明”，`-L` 和 `-l` 解决“找函数实现”。即使这些 demo 主要使用 libcrypto，使用 pkg-config 返回的完整 OpenSSL 参数也可以。

不要只复制源文件目录中的头文件来消除红线，也不要从其他电脑复制一个 DLL 就认为安装完成。编译器、头文件、链接库与运行库需要配套。

## 8. 编译成功，但签名或验签失败

先运行未修改的 demo 04。若它通过，环境大体可用，再检查自己的修改。

1. **消息是否一致？** 签名与验签必须使用同一段字节及相同长度。空格、换行、末尾 `\0` 是否计入长度也会影响摘要。
2. **摘要是否一致？** 本套 demo 先计算 SHA-256，再调用 `EVP_PKEY_sign` / `EVP_PKEY_verify`。不要在一端额外哈希一次。
3. **公钥是否对应？** 验签公钥必须属于签名使用的私钥；另生成一把密钥不能验证上次的签名。
4. **签名长度是否正确？** 使用签名函数写回的实际长度，不能直接把整个 128 字节缓冲区都作为签名传入。
5. **是否正确检查返回值？** `EVP_PKEY_verify` 返回 `1` 才是有效；`0` 表示未通过，负数表示其他错误。不要写 `if (result)`，因为负数也会被判断为真。
6. **是否把故意失败的实验当成故障？** demo 04/05 中篡改后验签失败，正是预期结果。

库函数在正常路径上失败时，可以临时添加 OpenSSL 错误输出：

```cpp
#include <cstdio>
#include <openssl/err.h>
```

在检测到库函数调用失败的分支内、紧接失败调用输出：

```cpp
ERR_print_errors_fp(stderr);
```

`stderr` 是标准错误输出；这个函数会打印并清空当前线程的 OpenSSL 错误队列。它没有返回值，也不能代替检查原函数的返回值。预期的“无效签名”不一定有额外错误文本。
