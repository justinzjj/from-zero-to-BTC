# 把这一笔付款对应到 Bitcoin Core v29.0

以下入口均固定到 v29.0。先沿普通交易的检查路径阅读，再看视图如何保存结果。

| 课堂观察 | 对应文件与符号 | 阅读时留意 |
|---|---|---|
| 两个输出同属一笔交易 | [primitives/transaction.h](https://github.com/bitcoin/bitcoin/blob/v29.0/src/primitives/transaction.h) 的 COutPoint、CTxIn、CTxOut、SerializeTransaction | prevout 的 n 索引 vout；锁定条件随输出保存 |
| 标识交易 | [primitives/transaction.cpp](https://github.com/bitcoin/bitcoin/blob/v29.0/src/primitives/transaction.cpp) 的 CTransaction::ComputeHash | txid 使用无见证序列化 |
| 保存可花记录 | [coins.h](https://github.com/bitcoin/bitcoin/blob/v29.0/src/coins.h) 的 Coin、CCoinsMap、CCoinsViewCache | Coin 还记录高度和 coinbase 标记；缓存容器是实现选择 |
| 基本格式、金额与重复输入 | [consensus/tx_check.cpp](https://github.com/bitcoin/bitcoin/blob/v29.0/src/consensus/tx_check.cpp) 的 CheckTransaction 和 [consensus/amount.h](https://github.com/bitcoin/bitcoin/blob/v29.0/src/consensus/amount.h) 的 MoneyRange | 无需 UTXO 视图即可检查这些规则 |
| 依赖旧状态的检查 | [consensus/tx_verify.cpp](https://github.com/bitcoin/bitcoin/blob/v29.0/src/consensus/tx_verify.cpp) 的 Consensus::CheckTxInputs | 从旧币取金额，核对输入覆盖输出并算手续费 |
| 消费与创建 | [validation.cpp](https://github.com/bitcoin/bitcoin/blob/v29.0/src/validation.cpp) 的 UpdateCoins；[coins.cpp](https://github.com/bitcoin/bitcoin/blob/v29.0/src/coins.cpp) 的 SpendCoin、AddCoins | 先消费输入，再按输出序号建立可用记录；Core 跳过可证明不可花的输出 |

## 真实字段与输出编码

- 查找键和旧输出分别对应 [v29.0 · COutPoint 与 CTxOut](https://github.com/bitcoin/bitcoin/blob/v29.0/src/primitives/transaction.h)。[Coin](https://github.com/bitcoin/bitcoin/blob/v29.0/src/coins.h#L22-L42) 保存 out 和高度、coinbase 元数据。
- [交易格式参考](https://developer.bitcoin.org/reference/transactions.html)给出输出的金额、CompactSize 脚本长度、脚本顺序。[BIP 141](https://bips.dev/141/#p2wpkh)规定 P2WPKH 的版本和 20 字节程序。课堂 100000 聪、顺序填充的哈希与高度 900003 为构造数据。
- 落盘格式补充阅读：[v29.0 · CoinEntry](https://github.com/bitcoin/bitcoin/blob/v29.0/src/txdb.cpp#L36-L41) 用前缀、哈希和 VARINT 序号作键；值的编码见 [Coin::Serialize](https://github.com/bitcoin/bitcoin/blob/v29.0/src/coins.h) 和 [TxOutCompression](https://github.com/bitcoin/bitcoin/blob/v29.0/src/compressor.h)。这些是 Core 的本地存储选择。
