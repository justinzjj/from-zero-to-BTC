# 05a · 输入见证的数据结构

见证（witness）是供节点核验花费条件的数据。每个输入对应的有序字节串列表称为见证栈（witness stack）。输入决定它要花哪个旧输出，旧输出的脚本决定见证需要提供哪些数据。对于原生 P2WPKH，列表第一项是附签名模式字节的签名，第二项是公钥。

验证者需要拿到满足旧输出条件的材料。把这些材料独立编码后，节点可以验证花费，并分别计算基本交易标识 txid 和覆盖见证的 wtxid。交易的输入输出关系依然可以用基本交易标识引用。

**列表怎样编码。** 每个输入先写见证项数，再按顺序写每项的字节长度和内容。项数、长度都是 CompactSize。P2WPKH 两项中的签名证明授权，公钥用于验签并与旧输出的公钥哈希比对。

**Core 表示与线路格式。** Bitcoin Core v29.0 的 `CScriptWitness::stack` 是 `std::vector<std::vector<unsigned char>>`。外层下标选中一项，内层存该项的原始字节。公开 BIP143 向量中的一个输入编码为 `02 | 47 | 70字节DER签名及1字节模式 | 21 | 33字节公钥`；02、47、21 均为十六进制。

**英文术语**　P2WPKH（Pay to Witness Public Key Hash，支付到见证公钥哈希）、DER（Distinguished Encoding Rules，可辨别编码规则）、txid（transaction identifier，交易标识）、wtxid（witness transaction identifier，含见证交易标识）、BIP（Bitcoin Improvement Proposal，比特币改进提案）。
