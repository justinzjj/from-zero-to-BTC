# 11｜B 和 C 都想花 U，Bob 的节点记哪一笔？

内存池是每个节点自己维护的待确认交易集合。接纳 B 表示这个节点愿意暂存它，Bob 的钱包可以显示「待确认 60,000 聪」。

Bob 收到 B，先后要核对交易结构、输入能否在当前链或本池父交易中找到、金额、时间约束及脚本与签名。单笔入池还受本地中继费率、池满时的动态门槛以及其他策略制约。接纳后，Core 的 mapTx 保存交易条目等信息；mapNextTx 用完整旧输出引用（前序 txid、输出编号）查池内谁正在花它。此时能查到 U → B，链上已确认 UTXO 集里的 U 仍在。

竞争交易 C 也引用 U，节点便找到与它直接冲突的 B。Core v29.0 对普通单笔替换已不要求原交易预先发出可替换信号。它仍检查 C 的费率是否超过各直接冲突者、总费用是否覆盖被逐出交易及其后代、增量费用是否足够支付新交易带宽等；对新增未确认输入和逐出数量也有限制。测试假设 B 没有后代，C 为 140 vB，本机增量中继费率为 1 聪/vB。B 已付 1,000 聪，则光是增量费用一项就要求 C 至少付 1,140 聪；达到这个金额仍须通过其他检查。

| Bob 观察到的事件 | 本地池中的 B、C | 已确认 UTXO 视图 |
|---|---|---|
| 接纳 B | B 占用 U | U 仍可按 outpoint 查到 |
| 接纳满足替换条件的 C | 移除 B 和依赖它的后代，改为 C 占用 U | U 仍在 |
| 验证并连接含 B 的有效块 K | 清掉已确认的 B（若在池），移除与 B 冲突的 C 及其后代（若在池） | 花掉 U，新增 B:0、B:1（假定块内无后续花费） |

在这个例子中，费用 1,139 聪比增量门槛少 1 聪，替换失败。符合共识的 C 仍有可能由矿工收入区块。

**英文术语**　UTXO（Unspent Transaction Output，未花费交易输出）、txid（transaction identifier，交易标识）、vB（virtual byte，虚拟字节）。
