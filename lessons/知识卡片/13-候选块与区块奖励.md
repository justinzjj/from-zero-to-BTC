# 13　矿池在候选块里能给自己写多少钱？

候选块是矿池准备拿来尝试 PoW 的一份完整区块方案。矿池选哪些交易属于自己的策略，Bob 会独立检查最终区块里的每一笔交易。

**从 U 算到奖励。** B 花掉 100,000 聪，写出 60,000 和 39,000 聪，剩下的 1,000 聪是手续费。矿池如果把 B 放进 K，可以在块首的一笔特殊交易 coinbase 中多领取 1,000 聪。coinbase 使用一个空前序引用，输入脚本在现行主网高度要以区块高度开头，输出脚本指定领取者。在本课的池化挖矿部署中，领取者可以是矿池，矿工之间的分账按矿池合同另算。

| Bob 验 K 时检查什么 | 如何核算 |
|---|---|
| 领取上限 | coinbase 全部输出之和 ≤ 该高度补贴 + 块中全部普通交易的费用。允许少领，多领一聪也会导致整块无效。 |
| 减半 | 主网从 50 BTC 起，每 210,000 块将整数聪补贴折半并向下取整。假设 K 高度为 840,000，补贴为 312,500,000 聪，只含 coinbase 和 B 时最多可领 312,501,000 聪。这里的高度是示例高度。 |
| 成熟期 | 花费 coinbase 时，花费所在块高度减去创建高度须至少为 100。高度 840,000 的奖励最早可在 840,100 花费。B:0 是普通交易输出，Bob 可以在满足其脚本条件时花费它。 |
| 区块资源 | 块重量 = 3 × 去见证序列化字节数 + 完整序列化字节数，最多 4,000,000 WU。签名操作另按脚本类型计成本，每块最多 80,000 成本单位。二者分别检查。 |
| 交易依赖 | 若同块内一笔交易花费另一笔的输出，创建输出的交易必须先执行。B 与竞争交易 C 都花 U，无法一起执行成功。 |

领取 312,501,001 聪比本例上限多 1 聪，即使区块头哈希达标，整块仍无效。

**英文术语**　PoW（Proof of Work，工作量证明）、BTC（bitcoin，比特币的单位符号）、WU（weight unit，重量单位）。

**规范与实现**　[Bitcoin Core v29.0 验证代码](https://github.com/bitcoin/bitcoin/blob/v29.0/src/validation.cpp) · [Core v29.0 共识常量](https://github.com/bitcoin/bitcoin/blob/v29.0/src/consensus/consensus.h)
