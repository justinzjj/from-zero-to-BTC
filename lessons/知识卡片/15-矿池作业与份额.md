# 15　普通份额和有效区块，谁收到哪一种？

本例采用经典 Stratum V1 作业。份额是矿池按自己设定的较宽松门槛承认的一次计算结果，用于估计贡献、按约定记工。

| 谁行动 | 收到什么，交出什么 |
|---|---|
| 矿池模板构造器 | 从池方全节点取得父块和可选交易，选入 B，安排交易顺序、coinbase 与见证承诺。保留完整模板以便之后重建 K。 |
| 矿池作业协调器 | 为模板分配作业号 J。经典 V1 的订阅结果提供会话 extraNonce1 和 extraNonce2 长度，作业通知再给 coinbase 两段、父块哈希、从 coinbase 到根的 Merkle 分支、版本、nBits、时间和是否清理旧作业。份额难度可由单独消息分配。 |
| 矿场控制器 | 选择 extraNonce2，按约定把两个额外 nonce 嵌入 coinbase。算 coinbase 的 txid，沿分支算出普通 Merkle 根，构造头并分任务给芯片。更换 extraNonce2 会换一片 nonce 搜索空间。 |
| ASIC | 对分配到的区块头尝试不同的 32 位 nonce，算双 SHA-256，回报候选 nonce 及相应任务。芯片完成每次尝试只需头部计算材料。 |
| 控制器与矿池 | 控制器以 worker、J、extraNonce2、时间和 nonce 提交。矿池从会话和作业重建同一个头，复算、查重复与作业有效性。达到份额目标可按池规则记工，达到网络目标还应重建含见证的完整 K，交给节点验块并传播。 |

设池的份额目标为 S，网络目标为 T，且 S > T。哈希值落在 T < h ≤ S 时，矿池可记工；h ≤ T 时，池方可重建并提交完整区块。Bob 的书款要等他的节点采用含 B 的块才获得确认。

**英文术语**　SHA-256（Secure Hash Algorithm 256-bit）、ASIC（Application-Specific Integrated Circuit，专用集成电路）、txid（transaction identifier，交易标识）。

**规范与实现**　[BIP 22 模板接口](https://bips.dev/22/) · [Bitcoin Wiki 的 V1 消息说明](https://en.bitcoin.it/wiki/Stratum_mining_protocol)
