# 16　两名矿工同时出块，Bob 的节点跟哪一边？

两个矿工都找到达标的头，只说明两份 PoW 都合格。各节点还要验证区块内容，并在自己已知、可验证的有效分支中采用累计工作量最大的一条。网络延迟允许大家短暂采用不同链尖。

| 时刻 | Bob 的节点 | 另一个节点 |
|---|---|---|
| 父块 P | 活动链的 U 还在，B 要把它付给 Bob。 | 同样从 P 出发。 |
| K 和 L1 几乎同时产生 | 先收到并采用 K，其中 B 花 U。Bob 看见 60,000 聪获得 1 次确认。 | 先收到并采用 L1，其中 C 花同一个 U。按这条分支，B 与 C 冲突。 |
| 两边都收齐两个块 | K 与 L1 各自基于 P，各自可以有效。累计工作平手，Bob 可以继续用 K。 | 同样可以继续用 L1。节点无须先统计有多少邻居支持哪边。 |
| L2 有效地延长 L1，且该支累计工作领先 | Bob 找到最近共同祖先 P，断开 K，恢复 U，移除 B 的两个输出。依次接入 L1、L2，C 花掉 U。钱包保留 B 的交易记录，并把它标为冲突，60,000 聪退出已确认余额。 | 在 L1 上接 L2。两个节点得到同一活动链。 |

**「最长链」怎样量？** 单块工作量为 `floor(2²⁵⁶ / (T+1))`，体现该目标下找出一个合格哈希通常有多难。对同一个 T，运气特别好、找到更小哈希的矿工所得工作量也相同。区块索引累加父块工作量和本块工作量，得到 `nChainWork`。本例假设各块同一难度，一块对两块时，后者多一块的工作量。跨难度时期要逐块相加。可用第 14 卡创世块的真实目标复算：Python 表达式 `(1 << 256) // ((0xffff << 208) + 1)` 给出 4,295,032,833。

**平手时谁先？** Core v29.0 在普通运行中用本地序号等信息给同工作量的候选排序，通常有利于较早取得完整数据的分支。收到区块头的时刻、区块的自报时间戳、任一观察者看到的先后，都无法建立全网统一的“第一名”。若 L2 比 L1 的块体先到，Bob 需要取得缺失的祖先数据、验证父链，才能把这个分支接为活动链。

无效祖先上的后继工作量无法使该分支有效。节点只在符合共识的分支之间比较累计工作量。

**英文术语**　PoW（Proof of Work，工作量证明）。
