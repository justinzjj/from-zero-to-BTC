# 读取一笔完整交易并复算字节

UTXO 是 *unspent transaction output*，即还可以花的一项交易输出。Bob 看到的余额来自钱包汇总它识别的输出。节点要判断某笔钱能否花，就查询具体的输出。

## 从历史交易算出当前余额

把旧交易按活动链顺序读一遍：每遇到一个普通输入，就按 outpoint 删掉它花费的那一项；每遇到一个可进入 UTXO 集的新输出，就按 (本交易 txid, 输出序号) 加入金额、脚本及验证所需元数据。钱包可以只跟踪和自己有关的记录，再按「我识别的脚本、是否已花费、是否已确认」筛选求和。节点维护全网可花输出；钱包可另列待确认、尚未成熟或仅观察的款项。

只看这笔书款，Bob 起初已确认 0 聪。B 入池时已确认仍为 0，待确认增加 60,000。K 接入后 B:0 转为已确认 60,000，待确认回到 0。随后，Bob 后来花掉整个 B:0，新的已确认交易不再给自己找零。这时 B 仍在历史里，B:0 对当前余额的贡献为 0。如果简单累加所有历史收款，就会重复计入已花的钱。

## 书款如何改变 UTXO 集？

用 `(前序 txid, 从 0 起算的输出编号)` 作键，这个二元组叫 **outpoint**。节点的链状态在该键下保存金额、scriptPubKey，以及创建高度、是否 coinbase 等验证所需信息。本例中 U 的键为 `(11 重复 32 字节, 0)`，值中有 100,000 聪和 Alice 的脚本。钱包还会把相关输出与自身密钥或描述符对应起来。

| Bob 的节点走到哪一步 | 可在活动链 UTXO 集里查到什么 |
|---|---|
| B 入内存池 | 仍能查到 U。内存池另行登记 B 占用 U |
| 含 B 的 K 成为活动链尖 | 连接 K 时删除 U、写入 (txid_B,0) 的 60,000 聪和 (txid_B,1) 的 39,000 聪，假定块内无人接着花它们 |
| 若随后改采含 C 的分支 | 断开旧块时撤回 B 的输出、恢复 U，连接新分支时再由 C 消耗 U |

B 的输入在线路上只引用 U，不携带 U 的金额。节点查到 100,000 聪后才能核对手续费 `100,000 − 60,000 − 39,000 = 1,000`。手续费、所有者姓名、钱包余额与确认数都无需编码成交易字段。

## 带见证交易的完整线格式

| 顺序 | 字段及尺寸 | 如何定位下一项 |
|---|---|---|
| 1 | version，4 字节小端整数 | B 取 2 |
| 2 | marker、flag 各 1 字节，本格式为 00、01 | 基本格式省去两者 |
| 3 | 输入数，再重复各输入 | 每项为 32 字节前序哈希（相对常见 txid 显示逆序）、4 字节小端输出编号、scriptSig 字节长度及内容、4 字节小端 sequence |
| 4 | 输出数，再重复各输出 | 每项为 8 字节小端金额（聪）、scriptPubKey 字节长度及内容 |
| 5 | 每个输入各一份见证 | 按输入顺序逐一读元素数，再读每个元素的长度和字节 |
| 6 | locktime，4 字节小端整数 | 交易结束 |

表中的可变数量和长度都用 CompactSize。0–252 直接占 1 字节，253–65,535 写 fd 后接 2 字节小端，随后两个范围分别写 fe 后接 4 字节、ff 后接 8 字节，编码必须用最短形式。如 252 为 `fc`，253 为 `fdfd00`，300 为 `fd2c01`。因此 B:0 的 `16 00 14 …` 中，`16` 是字节长度 22，`14` 已经处在脚本内部。

**复算。** 把上面十一行粘贴为 Python 多行字符串 `sample`。这是每行按字段分组的专用小实验；切换样本时应按长度字段逐项解析。

```python
from hashlib import sha256
rows = sample.strip().splitlines()
full = bytes.fromhex(" ".join(rows))
base = bytes.fromhex(" ".join(rows[:1] + rows[2:8] + rows[-1:]))
def displayed_id(raw):
    return sha256(sha256(raw).digest()).digest()[::-1].hex()
print(len(full), len(base), displayed_id(base), displayed_id(full))
```

应得含见证 343 字节、基本格式 233 字节。txid 为 `e8151a2af31c368a35053ddd4bdb285a8595c769a3ad83e0fa02314a602d4609`，wtxid 为 `c36c38370907df2324d9ce9d149d191192f338b37665a82e78e76a12c909b762`。

节点按 outpoint 精确查找旧币。即使金额相同，指向不存在输出编号的输入也无法通过检查。

**英文术语**　P2WPKH（Pay to Witness Public Key Hash，支付到见证公钥哈希）、P2PKH（Pay to Public Key Hash，支付到公钥哈希）、txid（transaction identifier，交易标识）、wtxid（witness transaction identifier，含见证交易标识）、BIP（Bitcoin Improvement Proposal，比特币改进提案）。
