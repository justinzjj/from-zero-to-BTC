# 复算签名摘要和中间哈希

在原生 P2WPKH 花费中，BIP143 规定签名摘要的编码方式。本例使用 SIGHASH_ALL。

B 是花费原生 P2WPKH 旧输出 U 的交易。生成签名之前，Alice 的签名器先为**正在花 U 的这个输入**生成一份 32 字节摘要。Bob 的节点以后从自己的 UTXO 视图取回 U 的真实金额与脚本，按同一规则重算摘要，再用见证内的公钥验签。签名摘要、交易标识 txid 各有自己的序列化输入。

**在本例的 SIGHASH_ALL（0x01）下**，签名器按以下次序拼字节，然后做两次 SHA-256。

| 顺序 | 拼入的数据 | 数据来自哪里 |
|---|---|---|
| 1–3 | 交易版本、hashPrevouts、hashSequence | B 的版本，以及对全部输入的 outpoint 串、全部输入的 sequence 串分别取双 SHA-256 |
| 4–7 | 当前 outpoint、带长度的 scriptCode、前序输出金额、当前 sequence | 当前输入指出 U。签名器另取 U 的花费条件和 100,000 聪；金额写成 8 字节小端序 |
| 8–10 | hashOutputs、locktime、4 字节签名类型 | 逐个序列化全部输出并拼接后取双 SHA-256（不加输出个数），再放锁定时间和 01000000 |

U 的 scriptPubKey 为「00 14 + Alice 的 20 字节公钥哈希」。签名器从 U 取该哈希，构造 25 字节脚本 76 a9 14 … 88 ac，前置长度 19（十六进制）得到此输入的序列化 scriptCode。B:0 上的 22 字节锁定脚本用的是 Bob 的公钥哈希，它通过 hashOutputs 被同一签名绑定。签名类型在摘要末尾占 4 字节，而见证内签名的末尾只附 1 字节 01。

**可复算练习**　切到 BIP143 的 Native P2WPKH 官方向量。它有两个输入，正在签的是第二个输入，旧输出为 6 BTC。以下是官方样例的两个序列化输出，可以直接用 Python 3 复算 hashOutputs。保留下方的字节顺序，结果与规范的中间值直接比。

```python
from hashlib import sha256
outputs = bytes.fromhex(
    "202cb206000000001976a9148280b37df378db99f66f85c95a783a76ac7a6d5988ac"
    "9093510d000000001976a9143bde42dbee7e4dbe6a21b2d50ce2f0167faa815988ac"
)
print(sha256(sha256(outputs).digest()).hexdigest())
# 863ef3e1a92afbfdb97f31ad0fc7683ee943e9abcf2501590ff8f6551f47e5e5
```

在同一例中，规范列出的完整 hash preimage 经双 SHA-256 后应得 c37af31116d1b27caf68aae9e3ac82f1477929014d5b917657d0eb49478cb670。示例交易 B 只给了金额和角色，因此没有可据此唯一确定的签名摘要。

SIGHASH_ALL 覆盖找零输出。节点从实际输出重算 hashOutputs，使用原摘要产生的签名无法授权另一个找零金额。

**英文术语**　UTXO（Unspent Transaction Output，未花费交易输出）、P2WPKH（Pay to Witness Public Key Hash，支付到见证公钥哈希）、SHA-256（Secure Hash Algorithm 256-bit）、txid（transaction identifier，交易标识）、BTC（bitcoin，比特币的单位符号）、BIP（Bitcoin Improvement Proposal，比特币改进提案）。

**规范与实现**　[BIP143 · Native P2WPKH](https://bips.dev/143/#native-p2wpkh) · [BIP134 · Flexible Transactions](https://bips.dev/134/)
