# 复算创世块并推导难度调整

矿池根据候选块 K 的父链计算规定的目标，将其压缩编码填入 nBits。Bob 从同一条父链独立推算期望的 nBits，再检查哈希整数不大于解码得到的目标 T。

**把哪些字节交给哈希函数？** 按线上的顺序串接版本（4 字节）、父块哈希（32）、交易 Merkle 根（32）、时间戳（4）、nBits（4）和 nonce（4），正好 80 字节。四个整数按小端序列化。常见浏览器显示的两个 32 字节哈希需逐字节反转后写入头。第二次 SHA-256 直接读取第一次的 32 字节摘要。假设每个摘要等可能，单试成功概率为 `(T+1)/2²⁵⁶`。T 越小，预期要试的次数越多。

**主网怎样调难度？** 除创世块外，新高度不是 2016 的倍数时，沿用父块 nBits。遇到边界，取上一周期末块时间戳减首块时间戳，涵盖 2015 个间隔。把时间差限制在 3.5 至 56 天，计算 `旧目标 × 限制后的秒数 ÷ 1,209,600`，作整数除法，结果受主网最大目标限制，再编码为 nBits。对通常的正目标，nBits 高字节为指数 e，低 23 位为系数 m，e ≥ 3 时目标为 `m × 256^(e−3)`。例如 0x1d00ffff 代表 65535 × 256²⁶。节点检查目标须为正、可表示且在允许范围内。矿池把 nBits 自行放宽，即便哈希低于所填目标也通不过期望值检查。

**回到 K。** ASIC 搜索的头通过 Merkle 根绑定含 B 的交易安排。为了直接复算，以下换用**主网创世块**头。这里的 nonce 和哈希属于创世块。

```python
from hashlib import sha256
from struct import pack

root = bytes.fromhex("4a5e1e4baab89f3a32518a88c31bc87f618f76673e2cc77ab2127b7afdeda33b")
target = 0xffff << (8 * (0x1d - 3))
for nonce in (2083236893, 2083236894):
    header = pack("<I", 1) + bytes(32) + root[::-1] + pack("<III", 1231006505, 0x1d00ffff, nonce)
    digest = sha256(sha256(header).digest()).digest()
    print(len(header), digest[::-1].hex(), int.from_bytes(digest, "little") <= target)
```

创世块的区块头长 80 字节，显示哈希为 `000000000019d6689c085ae165831e934ff763ae46a2a6c172b3f1b60a8ce26f`，满足网络目标。

**英文术语**　SHA-256（Secure Hash Algorithm 256-bit）、PoW（Proof of Work，工作量证明）、ASIC（Application-Specific Integrated Circuit，专用集成电路）。
