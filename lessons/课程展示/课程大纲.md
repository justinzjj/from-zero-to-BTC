## 展示纵览

| 课程 | 基本概念／算法与数据结构 | 对应代码实践 | 学到什么／积累什么能力 |
|---|---|---|---|
| 1. 字节、金额与确定性编码 | 整数聪、字节序、确定性序列化、SHA-256 | 写金额解析、交易草稿编码和哈希函数接口 | 把付款信息变成各节点一致理解的字节与标识 |
| 2. 密钥、哈希与数字签名 | 私钥/公钥、椭圆曲线、ECDSA、HASH160 | 调用成熟库生成密钥、签名验签；篡改消息测试 | 证明谁授权了付款，理解签名与保密的区别 |
| 3. UTXO 与最小账本 | UTXO、outpoint、输入/输出、找零、金额守恒 | 用映射表执行付款，删除旧输出并创建新输出 | 维护可花资金状态，识别重复花费 |
| 4. 授权验证与共用检查核心 | 花费条件、签名摘要、验证上下文、原子提交 | 实现共用交易验证器，拒绝盗花、超额输出与双花 | 让账本只接受授权且合法的状态变化 |
| 5. 地址、脚本与交易字段对照 | Bech32、P2WPKH、scriptPubKey、交易字段 | 解析付款URI和地址，还原收款脚本，拆解真实交易 | 连接用户看到的地址与节点执行的花费条件 |
| 6. 签名摘要、见证与交易标识 | BIP143、SIGHASH_ALL、DER、见证栈、txid/wtxid | 复算官方签名摘要，拆装见证，验证篡改后失败 | 明确签名绑定哪些数据，读懂Bitcoin交易授权 |
| 7. 密钥管理、归属与HD钱包 | 密钥库、脚本归属索引、BIP32、链码、描述符 | 管理密钥与归属；派生收款位置并恢复 | 钱包能认出自己的输出，找到正确的签名密钥 |
| 8. 付款界面、选币与费用 | 选币、找零、费用、分类余额、weight/vsize | 做CLI付款流程与贪心选币；按vsize估费 | 把付款意图组装为可签名交易，避免余额与费用错误 |
| 9. Merkle 树、证明与见证承诺 | Merkle树、包含证明、见证承诺、SPV边界 | 生成并验证交易包含证明；计算并验证见证承诺 | 用一个根绑定交易集合，区分包含证明与交易有效性 |
| 10. 区块、索引与单机链 | 区块头/块体、父指针、索引、按序执行 | 打包交易、接块并重放；非法交易导致整块拒绝 | 将合法交易组成可验证、可重放的单机历史 |
| 11. 交易池、策略与模板选取 | 交易池、冲突索引、父子依赖、策略与共识 | 接纳交易、排除冲突、排序打包和接块清池 | 管理待确认交易，为矿工提供可一起执行的候选交易集 |
| 12. PoW、奖励与挖矿模板 | PoW、target、nonce、coinbase、奖励成熟期 | 构造模板、搜索nonce，检查工作量与奖励 | 形成单机挖矿闭环，理解出块成本和发行约束 |
| 13. 共识问题与有效分支选择 | 区块树、chainwork、安全性/活性、概率确认 | 模拟同时出块，在有效分支中比较累计工作量 | 面对不同历史，知道如何选择活动链 |
| 14. 接块、断块与链状态重组 | 共同祖先、接块/断块、状态回滚、undo思想 | 切换B/C竞争分支，重放新链并复查回池交易 | 历史改变时恢复正确账本，理解确认可能被撤销 |
| 15. 验证事件分发与一致性边界 | 事件总线、订阅、顺序、状态版本、幂等 | 发布入池/接块/断块事件；注入重复通知与订阅失败 | 把验证结果可靠地传给其他组件，避免状态错序 |
| 16. 钱包—节点接口与交易状态 | 提交/查询/订阅接口、钱包交易状态、冲突索引 | 连接两个钱包与节点，联动付款、确认和重组 | 完成钱包到全节点的业务闭环，区分接纳与确认 |
| 17. P2P 连接与消息传输 | 邻居连接、消息分帧、收发队列、超时、背压 | 拆成三个进程，处理半包、粘包和慢接收方 | 让节点可靠交换完整消息，控制通信资源 |
| 18. 通告、请求、同步与网络分区 | 通告/请求、去重、headers/block、缺父同步 | 传播交易，补齐历史；断网挖矿后重连收敛 | 新节点能追赶历史，节点能从网络分歧中恢复 |
| 19. 节点与钱包持久化恢复 | 区块存储、钱包记录、检查点、重放/重扫 | 节点与钱包重启恢复，模拟提交后通知前崩溃 | 保留资金控制与交易历史，修复状态和通知缺口 |
| 20. 难度、时间规则与攻击实验 | 难度调整、时间锁、规则版本、资源限制 | 注入畸形消息与非法重分支；编写时间与难度规则验证算例 | 解释系统成立的条件，验证失败时仍维护不变量 |
| 21. 矿池作业、份额与虚拟矿机 | 模板/作业、job ID、份额目标、nonce分片 | 搭建一个协调器与两个虚拟工人，核验份额和出块 | 理解矿池协作，区分普通份额与网络认可的区块 |
| 22. 综合验收与Bitcoin Core对照 | 模块集成、因果日志、一致性检查、协议差异 | 集成：运行三节点两钱包，完成付款、分叉、重组和恢复 | 独立搭建、演示并解释完整简易区块链系统 |

## 1. 课程目标与深度约定

所有必修围绕一个UTXO教学链积累，最终在本机启动三个独立节点和两个钱包，完成付款、独立验证、传播、挖矿、分支选择、重组、同步、持久化及恢复。沿用Alice花U的100000聪，Bob收60000聪、找零39000聪、手续费1000聪；C竞争花同一个U。

本轮明确补入：第15讲验证事件分发、第16讲钱包—节点接口与交易状态、第17讲传输分帧与队列、第19讲通知缺口与钱包恢复、第21讲矿池作业和虚拟矿机。第5–8讲拆开地址、见证、密钥管理和选币，避免把所有Bitcoin细节塞进“最小钱包”一节。

| 深度 | 学生必须交付什么 | 与主项目的关系 |
|---|---|---|
| 基础实践 | 实现或接入指定能力，提交正常与失败用例 | 进入教学链累积项目；密码学可调用成熟库 |
| 基础概念 | 能解释原理与数据结构，并完成纸笔、官方向量或小程序对照实验 | 所有学生必须完成，但不要求把完整Bitcoin兼容机制并入教学链 |
| 专题扩展 | 在必修基线之上完成指定协议兼容、优化或工程实验 | 选做E1–E6，不影响必修结课 |

“基础概念”不是只听不做；“有专题扩展”不意味着必修可以跳过该机制的基本原理。所有上一轮列出的技术点已有明确落点，新增细化项也列在附录。覆盖统计指**教学安排完整性**，不表示已实现全部Bitcoin协议。

默认学生具备基础编程能力，区块链零基础；沿用已有C++背景，具体实现语言仍可调整。每讲按2小时课堂＋1–2小时作业估算，第0讲与22节共约46小时课堂、22–44小时作业。第6、14–19讲难度较高，可各拆为两次；不应为了固定课时删掉失败实验。每个专题扩展专题建议4小时课堂及独立作业，6个专题不要求全选。

## 2. 现有材料与实现边界

- [第0讲与付款旅程](../00-overview/0-BTC%20overview.md)、部署/钱包/全节点原图作为导航，不改动原HTML。
- [钱包模块清单](../00-overview/钱包模块算法与数据结构清单.md)和[知识卡](../知识卡片/README.md)用作逐讲推演材料。旧卡片的八讲编号属于历史归课，以本大纲新编号为准。
- 原[单机C++样例](../../../mini_blockchain/README.md)采用账户余额、教学哈希与RSA，保留为对照。新主线统一用UTXO、SHA-256与成熟库secp256k1 ECDSA，不在两种账本模型间切换。
- 主项目采用自定义确定性交易编码、单签花费条件、固定低难度、静态邻居、命令行界面。共同创世块、初始分配、奖励/成熟参数、目标和链标识统一配置。第3–11讲可暂用共同创世分配；第12讲加入奖励与成熟规则。
- Bitcoin对照实验和主线代码分目录。教学链签名绑定自定义链标识；BIP143对照必须保持标准向量原样，不把教学字段插入标准摘要。
- 第5讲基础概念v0 Bech32，说明v1+改用Bech32m；完整支持放E1。第6讲限v0 P2WPKH/BIP143，不称为所有Bitcoin签名算法。BIP32与描述符基础概念并做恢复对照；完整钱包兼容放E1。
- 不要求从零实现SHA-256轮函数、大整数或正式曲线密码学。网络框架可提供socket，但学生必须验证分帧、消息处理、队列边界与同步行为。

## 4. 每讲内容、实践与验收

<a id="lesson-1"></a>

### 第1讲 · 字节、金额与确定性编码

- **先修与模块：** 第0讲；W1、W5。
- **基本概念与技术细节：** 整数聪、BTC文本、字节序、十六进制、摘要与编码歧义。
- **算法原理：** 十进制字符串精确换算；确定性序列化；SHA-256与双SHA-256的调用边界。
- **简单实践：** 实现金额解析和交易草稿编码；同一输入跨节点得到同一字节。
- **验收与失败例：** 0.00060000精确得到60000；拒绝超8位小数、负数和溢出；修改一个字段改变摘要。

<a id="lesson-2"></a>

### 第2讲 · 密钥、哈希与数字签名

- **先修与模块：** 1；W2、W6。
- **基本概念与技术细节：** 私钥、公钥、授权、压缩公钥、HASH160；签名不等于保密。
- **算法原理：** 模逆、点加、倍点、标量乘法与ECDSA关系；密码学使用成熟库。
- **简单实践：** 小曲线纸笔推演；生成secp256k1密钥，复算压缩公钥与HASH160；签名验签。
- **验收与失败例：** 改消息或公钥后失败；随机数错误的后果能解释；玩具曲线代码不接入主链。

<a id="lesson-3"></a>

### 第3讲 · UTXO 与最小账本

- **先修与模块：** 1；W5、N8。
- **基本概念与技术细节：** outpoint、输入输出、找零、手续费、账户模型对照。
- **算法原理：** UTXO映射、金额守恒、重复输入检查、状态转移。
- **简单实践：** 用U的100000聪构造B：60000收款、39000找零、1000费用。
- **验收与失败例：** 重复花U失败；拒绝负数/超额输出；暂不带签名的阶段明确不能防盗花。

<a id="lesson-4"></a>

### 第4讲 · 授权验证与共用检查核心

- **先修与模块：** 2, 3；W5、W6、N3、N5、N8。
- **基本概念与技术细节：** 单签花费条件、签名摘要与txid、验证状态上下文。
- **算法原理：** validate_tx与apply_tx分离；绑定链标识、输入位置、旧币资料和输出；临时视图原子提交。
- **简单实践：** 接入成熟签名库，构造正常、盗花、篡改、重复输入交易。
- **验收与失败例：** 全部非法交易不改变账本；后续入池和验块复用此函数，不复制两套规则。

<a id="lesson-5"></a>

### 第5讲 · 地址、脚本与交易字段对照

- **先修与模块：** 4；W2、W3、W5、N5。
- **基本概念与技术细节：** P2WPKH、scriptPubKey、版本/输入/输出/nSequence/nLockTime、CompactSize；付款URI。
- **算法原理：** Bech32 polymod和5/8位转换；网络及见证版本检查；地址还原脚本。
- **简单实践：** 基础概念对照实验：解码一条v0地址、解析付款URI，按字段拆一笔真实交易。
- **验收与失败例：** 错误校验和/错误网络/不支持版本明确拒绝；能指出地址、脚本、输入引用的区别；扫码不是基础实践。

<a id="lesson-6"></a>

### 第6讲 · 签名摘要、见证与交易标识

- **先修与模块：** 5；W6、W7、N5。
- **基本概念与技术细节：** BIP143、SIGHASH_ALL、scriptCode、DER、逐输入见证栈、txid与wtxid。
- **算法原理：** 为v0 P2WPKH重建摘要；见证序列化；单签栈消费过程。
- **简单实践：** 基础概念对照实验：使用BIP143同一测试向量复算摘要和验签；拆签名与公钥两项见证。
- **验收与失败例：** 修改旧币金额或收款输出后失败；标记签名模式字节的位置；不得混用教学B和官方向量。

<a id="lesson-7"></a>

### 第7讲 · 密钥管理、归属与HD钱包

- **先修与模块：** 2, 5；W2、W8、W10。
- **基本概念与技术细节：** BIP32、HMAC-SHA512、链码、扩展密钥、普通/硬化派生、描述符与只读钱包。
- **算法原理：** 主线实现密钥和脚本归属索引；HD调用库并对照测试向量；保留派生位置。
- **简单实践：** 构建最小密钥库；对照实验派生两个收款位置并按同一路径恢复。
- **验收与失败例：** 主线可找到签名密钥和找零脚本；对照恢复不重复派生位置；解释链数据不能替代私钥。

<a id="lesson-8"></a>

### 第8讲 · 付款界面、选币与费用

- **先修与模块：** 3, 4, 7；W1、W3、W4、W5、W9。
- **基本概念与技术细节：** 可花/已确认/未确认余额、付款确认、贪心选币、找零、weight/vsize与费率。
- **算法原理：** 主线用确定性费用规则；BTC样例按vsize估费并在输入变化后重估；BnB讲思路。
- **简单实践：** CLI展示收款方、金额、费用和找零后签名；节点暂用测试适配器；BTC估费做独立对照。
- **验收与失败例：** 余额不足拒绝；精确付款/找零边界正确；用户取消不签名；不能把固定费说成真实动态估费。

<a id="lesson-9"></a>

### 第9讲 · Merkle 树、证明与见证承诺

- **先修与模块：** 1, 6；D1。
- **基本概念与技术细节：** Merkle根、包含证明、普通交易树与见证承诺、SPV验证边界。
- **算法原理：** 自底向上构造、奇数叶子约定、对数路径；讲清witness commitment位置。

## 5. 钱包接口与事件分发的明确契约

以下是**教学项目自定义接口**，借鉴原图职责，不是Bitcoin Core接口逐字复刻。Core接口名可在固定版本[validationinterface.h](https://github.com/bitcoin/bitcoin/blob/v29.0/src/validationinterface.h)对照。

### 5.1 第15讲：节点事件

事件封装至少有 `node_id、epoch、seq、type、state_version、payload`。`seq`是在一个节点的一个运行epoch内单调递增的本地序号；不是网络共识顺序。重复投递按 `(node_id, epoch, seq)` 识别，重启后的epoch变化必须触发检查点重建或重扫，不能把旧序号套在新状态上。

| 事件 | 最小载荷 | 触发边界 |
|---|---|---|
| `mempool_added` | 交易对象、txid、接纳状态版本 | 单笔接纳与索引更新成功后 |
| `mempool_removed` | txid、原因confirmed/conflict/evicted、关联块（如有） | 池变更成功后；移除本身不代表链上冲突或确认 |
| `block_connected` | 完整块或可回读引用、高度、接块后的链尖与状态版本 | 验证通过且活动状态提交后；有效侧支尚未采用时不发此事件 |
| `block_disconnected` | 被断开的块、高度、断块后的链尖与状态版本 | 断块成功后；按旧链从尖端向共同祖先的顺序发出 |
| `reorg_finished` | 新链尖、最终状态版本 | 断旧接新以及相应池整理完成后；供钱包刷新一致快照 |

节点串行提交状态变化并生成对应有序事件。重组先逆序断旧块，再正序接新块。订阅者按事件携带的块与版本处理历史变化，不能用一个旧事件随意读取已经推进的当前状态。查询得到的快照也携带版本；钱包在重组完成前暂停新付款的可花选择或重新同步最终快照。

失败验收：无效块不发布成功接块事件；重复事件不重复记钱；某订阅者失败不撤销节点已提交状态，也不能无限阻塞验证线程。第15讲先实现有界本地事件队列，第19讲处理持久化与缺口恢复。

### 5.2 第16讲：钱包—节点边界

| 接口 | 返回内容与语义 | 必验收反例 |
|---|---|---|
| `submit_tx(bytes)` | txid、accepted/already_known/rejected、结构化拒收原因；若已知，附当前池/链状态 | 提交成功不代表确认；格式、签名、缺输入、冲突、策略拒收可区分 |
| `get_chain_state()` | tip hash、height、state_version | 重组后不能继续使用旧版本缓存作选币依据 |
| `get_transaction(txid)` | 节点已知的池/活动链位置或unknown | unknown不能被钱包擅自解释成“已确认”或“冲突” |
| `scan_outputs(owned_scripts, snapshot)` | 同一快照下匹配的输出、花费状态、Coin元数据 | 扫描UTXO只给当前可花输出，不能重建全部钱包历史 |
| `subscribe(cursor)` | 事件或明确的cursor_expired/resync_required | 通知丢失/epoch变化时恢复，而非静默漏记 |

钱包维护 `txid→相关交易记录`、`outpoint→多个已知竞争交易` 和可识别脚本索引。状态至少区分本地草稿、拒收、未确认、已确认和冲突；资金可花性另外计算。断块后重新核对池和新链，不能一律把交易设成未确认。确认深度只对当前活动链内交易计算；已花输出即使原交易确认数继续上升，也不增加可用余额。

### 5.3 第19讲：崩溃窗口与恢复

基础实践模拟“节点已提交，但钱包尚未收到事件就崩溃”。实现以下一种有明确边界的恢复方式：持久事件日志＋游标重放，或者钱包保存自己的交易/派生状态/扫描检查点后，按节点一致快照重扫链并核对当前内存池。事件交付允许至少一次，钱包负责幂等；不承诺天然exactly-once。

区块与UTXO不能重建已经丢失且从未上链的本地交易，所以必须保留钱包自己的未确认记录。重扫能恢复链上归属，无法替代丢失的私钥。SQLite对照使用新建示例库，不直接修改真实Core钱包文件。

## 9. 最终必修验收

1. 三节点共享创世块和规则；两钱包各有独立密钥，完成B的付款、广播、挖矿与独立验证。
2. 盗花、重复输入、超额输出、双花、无效PoW、超领奖励和未成熟奖励花费均被正确拒绝，失败不污染活动状态。
3. 交易提交返回结构化结果；接纳不显示为确认，重复提交和事件不重复记钱。
4. B/C分支切换时，日志证明先断旧接新；钱包撤销旧确认并识别冲突；已花输出不计入可花余额。
5. 半包、粘包、重复通告、未交付请求、缺父、分区与晚加入节点得到预期结果；有效工作量优势传播后链头和规范化UTXO摘要一致。
6. 节点和钱包重启正确；提交后通知前崩溃可以重放或重扫恢复；私钥、未确认记录与派生进度有独立保存策略。
7. 基础概念对照实验包含地址解码、BIP143/见证、HD恢复、vsize估费、时间/难度算例与矿池份额；每项有结果和边界说明。
8. 矿池模拟区分普通份额与有效块，拒绝错job和重复记工；真实ASIC实现不计必修。
9. 对照选定版本Core regtest，提交运行步骤、事件日志、正常及失败用例、协议差异清单。学时与代码行数不代替验收。
