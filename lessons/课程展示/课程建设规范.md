# 每节课的固定结构与内容要求

[课程大纲](课程大纲.md) · [知识点梳理](知识点梳理.md) · [第01课样例](../01-字节、金额与确定性编码/讲义.md) · [第02课样例](../02-密钥、哈希与数字签名/讲义.md)

## 一条贯穿全课的任务

每节课以一个具体系统任务开场，接住上节课留下的问题。正文只有两大部分：**基础知识**、**实验尝试**。基础知识按解决任务的先后组织；实验按相同顺序实现，不另开一套故事。

贯穿前两课的任务：Alice 输入“向收款标识 2 支付 0.00060000 BTC” → 精确金额 → 固定字节 → 摘要 → 签名 → 只有公钥的验证者核对授权。第3课再追问“这笔钱从哪里来，是否已经花过”。

## 固定版式

开头用一个短表交代：本课问题、**学习重点**、上一课输入、本课输出、前置知识、系统位置、建议课时。再给一条流程图。

“学习重点”紧接“本课问题”，在同一表格单元格内按以下四项明确列出，可用 `<br>` 换行：

- **概念：**本课具体学习的概念名称，不能只写“了解原理”等笼统目标。
- **算法：**具体算法或处理机制名称；说明关键推导与流程，区分新学内容和前课复用。
- **数据结构：**具体类型、结构及其用途；必要时标注字段、长度或实现形式。
- **掌握程度：**明确哪些要手算、推导、自己实现，哪些要理解流程并调用成熟库，以及暂不要求实现的范围。

学习重点必须与正文及实验对应，让学生在开始阅读时就知道本课学什么、做到什么程度。

### 第一部分：基础知识

按流程分成3–6个连续步骤，每一步回答以下问题。

技术小节先以具体的概念、算法、机制或数据结构名称命名，再在标题后的正文提出“要解决的问题”，随后展开设计理由、原理和实现。不得用问题或故事句代替技术章节名。第01课示例：“确定性序列化与小端整数编码算法”，随后提出“如何让不同机器得到相同字节”；“Reader 游标与有边界检查的反序列化算法”，随后提出“如何还原对象并拒绝坏数据”。第02课示例：“椭圆曲线公钥生成：有限域运算与标量乘法”，随后说明“如何从私钥生成公钥”；“ECDSA 数字签名算法：签名、验签与正确性”，随后说明授权问题。组合算法应点明各算法名称；数字签名、加密、哈希等术语须准确区分。

| 必填内容 | 写作要求 |
|---|---|
| 问题 | 从当前任务指出一个具体失败场景，给输入或反例 |
| 设计选择 | 为什么选这种表示、算法或结构；至少比较一个合理替代方案 |
| 原理 | 输入、输出、前置条件；算法步骤、公式或状态转移；公式符号必须定义 |
| 正确性 | 哪个不变量保证目标；能保证什么；哪一种错误仍然无法解决 |
| 实现 | 明确类型、字段、字段宽度、函数签名、错误语义、生命周期和代码位置 |
| 代价 | 定义输入规模；时间复杂度、辅助空间、线格式大小、内存大小；区分理论估算与实测 |
| 真实代码 | 固定版本、文件、符号；说明对应关系与教学简化；不要只有仓库首页链接 |
| 过渡 | 已经解决什么，因此下一步还缺什么 |

算法专题需要伪代码或可追踪的执行过程；密码学专题需要基础数学、输入输出、核心公式、可手算实例及安全假设；数据结构专题需要具体类型、查询/更新操作、内存布局与编码布局的区别。公式推导和代码路径应能互相定位。


### 从概念落到 Bitcoin 的具体算法

凡涉及算法，介绍抽象概念后，必须明确：**Bitcoin具体使用的算法名称、参数或变体、适用场景、输入输出流程、固定版本源码入口，以及本课实现的差异**。不能只写“椭圆曲线”“哈希”“树”等类别名称。

例如：椭圆曲线 → secp256k1参数 → Q=dG标量乘法 → ECDSA或BIP340 Schnorr的适用路径 → 对应摘要与编码 → Bitcoin Core/libsecp256k1入口。区分曲线、底层运算、签名方案和库，不将其合称一个“加密算法”。

同一机制有多个版本时明确按输出类型、协议版本或应用位置区分；教学小算例、教学系统自定义规则与Bitcoin实际规则分别说明。内部实现优化不等于共识强制算法；Bitcoin没有唯一实现策略的地方，写明这是固定版本的实现选择，不编造“Bitcoin统一采用”的结论。

### 第二部分：实验尝试

| 顺序 | 固定内容 |
|---|---|
| 1. 实验环境 | 编译器、语言、依赖版本、准备命令、工作目录 |
| 2. 本课要写什么 | 明确文件、函数、输入、输出；区分学生练习与可运行参考实现 |
| 3. 分步实验 | 每步对应前面的一个问题；先预测，再运行，再解释 |
| 4. 正常结果 | 固定输入与预期输出；随机结果明确标注；必要时提供标准向量 |
| 5. 失败实验 | 至少一个边界输入、一个主动篡改、一个系统接口误用；明确拒绝后状态 |
| 6. 代价观察 | 运行时间、数据长度、内存指标；给测量方法与环境，不伪造固定性能 |
| 7. 系统接入 | 本课导出的接口、下游调用者、复用位置、后续会被替换的临时结构 |
| 8. 验收与下一课 | 解释题＋代码结果＋失败结果；留下一个自然引出的下一课问题 |

## 目录与维护

```text
from-zero-to-BTC/
  code/
    lesson-01/
      foundations.hpp       # 第01课建立的基础接口；后续直接引用
      lab01.cpp
      run.sh
    lesson-02/
      crypto.hpp
      lab02.cpp
      toy_curve.cpp
      toy_curve_test.cpp
      run.sh
    lesson-NN/              # 下一课新增的系统代码、实验、测试和运行脚本
    build/lesson-NN/        # 构建输出，不纳入版本管理
  lessons/
    NN-课程名/
      讲义.md               # 基础知识＋实验尝试
      resources/            # 图、数据、参考材料与验证记录；不放实验源代码
```

所有课程的实验源代码、测试、运行与构建脚本统一放在 `from-zero-to-BTC/code/`；按 `lesson-NN` 追踪课程来源。第02课直接引用 `code/lesson-01/foundations.hpp`，不复制金额和编码实现。公共接口只保留一个实现；确有跨课组织需要时可提取到 `code/common/`，并同步更新所有调用者。

当前前两课采用 C++17 和 OpenSSL 3，沿用现有 C++ 背景。小曲线仅用于推导，不进入系统签名路径。脚本按自身位置解析路径，从任意工作目录启动均可；讲义中的命令明确以本课程目录为工作目录，例如 `bash ../../code/lesson-01/run.sh`。所有构建输出放 `code/build/lesson-NN/`；每课的验证记录仍放在该课的 `resources/`。

## 内容验收标准

- 每个算法均明确其Bitcoin具体对应、适用范围和源码入口；教学实现与实际协议的差异可辨认。

- 技术小节标题明确指出所讲概念、算法或数据结构，问题放在标题后的引入段。

- 开头表格包含“学习重点”，完整列出概念、算法、数据结构、掌握程度四项，并与正文和实验一致。

- 知识清单中的基础项都能在讲义中找到；补充项明确阅读位置或后续课次。
- 从一个输入走到一个输出；每个概念都能指出它在流程中的用途。
- 学生能够解释设计理由、推演核心算法、说明主要开销，而不只是调用函数。
- 编译命令可运行；预期输出与实际验证记录一致；测试包含真实拒绝路径。
- 协议编码有明确版本和字段；不能把内存对象直接视为网络字节。
- 教学系统自定义协议与 Bitcoin 标准对照分清；标准代码参考固定版本。
- 前两课的“付款草稿”不提前冒充完整交易；后续UTXO、共识、重放保护在对应课次完善。
- 课时不够时拆成同一课的上下两次，不删除算法推导、失败实验与系统接入。

## 学生代码的语法范围

依据学生提供的区块类代码，已展示的写法包括固定数组、循环、if、位运算、普通函数、typedef和简单class。新实验优先沿用这些语法；不默认学生掌握vector/string、模板、智能指针、异常、lambda或复杂资源管理。直接调用OpenSSL的学生版保留必要的指针与取地址操作，并逐行解释；不要为了减少语法而取消边界检查、返回值检查或资源释放。教学封装可保留作参考，初次演示优先使用直接库调用版本。

## 实践优先的讲解深度

以实际算法和系统接口的使用为主：给出必要原理后，尽快进入真实库调用、输入输出、正常流程、失败实验及系统接入。原理用于解释接口为何这样用，不要求每次从底层数学重新实现算法。

第二讲以真实secp256k1密钥生成、ECDSA签名与仅公钥验签为验收重点；模逆、点加、倍加、公式推导和小曲线nonce恢复保留在课后补充，不再作为课堂前置或验收要求。此安排优先于本规范中对数学手算的一般性要求。

## HTML 课堂展示规范

后续课程使用 HTML 展示，不制作 PPT。每讲在自己的目录交付 `课堂展示.html`，沿用第01、02讲和 overview 的深色技术工作台风格。

- 开头一页：课程标题、学习重点、学到什么、解决什么问题，以及所属组件和模块；可复用 overview 模块名称或架构图，突出本课范围并链接完整架构。
- 按讲义顺序分页：概念、数据结构、算法各自成页；长推导可拆页，先名称再问题，保留公式、步骤、正确性、复杂度、Bitcoin具体实现及教学差异。
- 随后进入实践：环境与命令、代码与讲解要点、正常结果、失败实验、性能与空间观察、系统接入。代码摘自 `code/` 的实际文件，不另存一套实验实现。
- 支持目录跳转、键盘翻页、全屏和连续阅读；小屏可纵向滚动，禁止用裁剪隐藏正文。讲义、代码、相邻课和 overview 提供相对链接。
- 优先无外部运行依赖；图片等材料放本课 `resources/`，共用构建工具放课程展示 `resources/`。前两讲由 `resources/build_lesson_html.py` 生成，维护源文件后重新构建。
- 检查桌面投影尺寸及窄屏排版，验证翻页、目录和交互，记录在本课 `resources/HTML验证记录.txt`。不因制作展示页而删减讲义。
