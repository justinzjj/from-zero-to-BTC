# Bitcoin 钱包模块 · 算法与数据结构清单

适用案例为原生 P2WPKH 交易 B，对照 Bitcoin Core v29.0 描述符钱包。编号对应[钱包组件架构图](btc-wallet.html)。每个勾选项可以单独展开一讲。

| 模块 | 算法或处理规则 | 关键数据结构 | 可以动手核对的结果 |
|---|---|---|---|
| ① 用户接口 | 十进制 BTC 金额按 8 位小数精确换算为整数聪，核对付款草稿 | 地址、整数金额、可选本地标签 | 0.00060000 BTC 对应 60,000 聪 |
| ② 密钥与脚本管理 | BIP32 子密钥派生（HMAC-SHA512）、secp256k1 标量乘法、压缩公钥的 HASH160 | 扩展密钥、收款与找零描述符、派生下标、脚本到下标的索引 | 同一收款位置可重建同一条锁定脚本 |
| ③ 地址与付款请求 | 解析付款 URI，Bech32 polymod 校验，5 位与 8 位分组转换，按见证版本和长度构造脚本 | 收款目的地、见证版本、20 字节公钥哈希、scriptPubKey | 地址解码后得到 00 14 加上 20 字节哈希 |
| ④ 可用币查询与选币 | 筛选可用输出，按虚拟大小和费率估费，搜索候选组合；Core 的可选策略包括分支限界搜索 | 旧输出引用 COutPoint、金额、脚本、候选输出组、费率 | U 的 100,000 聪覆盖 60,000 聪付款和给定的 1,000 聪费用 |
| ⑤ 交易构造 | 根据选币结果组装输入和输出，按索引分配付款与找零；改变输入或输出后可重估费用 | CMutableTransaction、vin、vout、CTxIn、CTxOut | B 的输入引用 U，输出 0 和 1 分别为 60,000 和 39,000 聪 |
| ⑥ 签名与见证装配 | BIP143 字段序列化、双 SHA-256、secp256k1 ECDSA、DER 编码，附签名模式字节 | scriptCode、旧输出金额、32 字节摘要、签名数对、见证栈 | 见证的两项为带模式字节的签名和 Alice 的压缩公钥 |
| ⑦ 节点接口 | 带见证序列化与提交，分派入池、接块和断块通知 | 交易字节、交易对象、区块及其哈希和高度 | Alice 提交给接入节点；Bob 的 Core 钱包接收同进程通知 |
| ⑧ 相关交易跟踪 | 扫描输出并匹配脚本，按输入引用查已知花费，处理冲突和确认状态变化 | 脚本索引、txid 到钱包交易的映射、旧输出引用到花费交易的多值索引 | 查 Bob 的脚本认出 B:0；查 U 发现 B 与 C 冲突 |
| ⑨ 钱包查询 | 按归属、花费和确认状态筛选，分类求和；按活动链高度差计算确认深度 | 钱包交易记录、输出引用、链上位置、分类余额 | 已确认与可花分别计算；一项输出花掉后原交易仍可增加确认 |
| ⑩ 钱包本地存储 | 通过 SQLite 持久化和读回键值记录，由记录重建运行时索引 | 描述符记录、派生进度、密钥资料、钱包交易记录 | 重启可恢复关注的脚本及已记录的交易 |
